# Sidebar and import beta verification

Date: 2026-11-02. The preview, layout, and scoped material-template changes pass the checks below. The end-to-end backup guard fails. The completed coverage matrices record a blocking FILES skeletal-body defect and explicit untested workflows. No candidate release has been installed.

## Sidebar changes

The selected Steam or FModel folder picker sits directly below the import-source dropdown. Settings no longer duplicates those pickers. Outfit Advanced follows Outfit Selector and contains Mask Debug. Add All Weapons and Include Ascended share a box. These changes use existing labels.

Appearance preview drawing queues image decoding and cropping instead of doing that work during draw. A timer prepares one queued image per tick. Failed images do not repeatedly queue, and unregister cancels pending work. The crop implementation and shipped artwork are unchanged.

Weapon texture preparation no longer creates an intermediate ImagePreview and converts its pixels to a Python tuple. It uses the prepared NumPy canvas directly and reproduces the original byte quantization. Each asset retains its existing preview rectangle and crop.

## Direct-PAK material-template results

The native compiler retains a bounded cache of pristine graph templates. A complete validated dependency signature is required before lookup. Every hit copies the pristine graph and creates independent material-root controls. Edits to an imported graph never become the template for later imports. Source, build, mapping, and loaded-code validation remain in place. The first graph still requires compilation.

The paired experiment alternates cache-disabled and cache-enabled charging-handle imports from the private direct-PAK extraction cache in the same Blender process after priming.
